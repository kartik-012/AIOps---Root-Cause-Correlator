## 🚨 The Operational Problem

> *"When a core microservice degrades, 50+ dependent services trigger cascading alerts simultaneously. On-call engineers spend 1 to 4 hours combing through logs to identify what actually broke."*

```
  Postgres Connection Pool Saturation           ← [ORIGINATING ROOT CAUSE]
                 │
                 ▼
       Payment Service (Latency spike: 920ms)
                 │
                 ▼
       Order Service (Timeouts & 504 errors)     ← ALERT FIRES
                 │
                 ▼
       API Gateway (Upstream error flood)       ← ALERT FIRES
                 │
                 ▼
       Frontend Checkout (Customer churn)       ← ALERT FIRES
```

### The Solution
Instead of guessing or passing alerts to an LLM without architectural context, **AIOps Root Cause Correlator** applies:
1. **Dynamic EWMA Anomaly Detection** to flag statistical variance without manual threshold tuning.
2. **Deterministic Graph Causality (NetworkX)** to trace propagation through directed service dependency topology.
3. **gRPC Protocol Buffer Diagnostics** to verify the hardware and connection state of the suspect service.
4. **Cosine Signature Memory** to suppress false alarms from recurring cron jobs or batch spikes.
5. **Counterfactual What-If Simulation** to prove what configuration change would prevent recurrence.

## 🧠 Principal SRE Architectural Capabilities

1. **MicroRCA++ Dynamic Edge-Weighted Personalized PageRank (`CorrelationEngine`)**: Replaces static uniform transition probabilities with log-scaled request-rate (`log1p(RPS)`) and empirical metric covariance edge weights, preventing hub-bias false positives on API Gateways.
2. **24-Hour Fourier Harmonic Diurnal EWMA (`DiurnalSeasonalBaseline`)**: Models daily traffic seasonality ($\mu + \sum [a_k \sin(k\omega t) + b_k \cos(k\omega t)]$) so expected 9:00 AM morning traffic surges do not trigger false alarms, while off-peak 3:00 AM spikes of the same magnitude immediately page on-call SREs.
3. **OpenTelemetry Distributed Trace Critical-Path Attribution (`TraceAttributionEngine`)**: Decomposes multi-hop distributed traces into interval-merged exclusive span execution times (`exclusive_time = duration - merged_children_wait`), isolating the exact SQL query or gRPC method responsible for tail latency.
4. **Lock-Free Streaming Ring Buffer with Backpressure (`StreamingRingBuffer`)**: Bounded `10,000`-event ingestion ring buffer with an `80%` high-watermark backpressure circuit that downsamples stationary nominal metrics by `75%` during alert storms while preserving `100%` of anomalous spikes.
5. **Canary Remediation Safety Circuit-Breaker (`execute_canary_with_safety_circuit_breaker`)**: Executes high-risk runbook actions on a `5%` canary slice, verifies post-remediation gRPC health telemetry, and triggers an automatic rollback (`ABORTED_ROLLED_BACK`) if error rates fail to recover.
6. **Online Thompson Sampling Bandit Runbook Ranking (`ThompsonSamplingRunbookBandit`)**: Maintains Beta-Bernoulli $(\alpha, \beta)$ posteriors and rolling MTTR per `(root_cause_type, action_id)`, learning online from production remediation outcomes.
7. **Multi-Tenant HNSW Vector Signature Partitioning (`SuppressionEngine` & `pgvector`)**: Scopes 7D cyclical cosine-similarity false-positive suppression across `(tenant_id, environment)` partitions.
8. **Automated Chaos GameDay Scenario Runner (`ChaosGameDayEngine`)**: Orchestrates end-to-end 4-stage production crisis drills (Fault Injection $\to$ Streaming Detection $\to$ Graph & Trace Isolation $\to$ Canary Remediation), measuring real-time **MTTD**, **MTTI**, and **MTTR**.
9. **Progressive Trust, Admin Investigation Mode & Real-Phone Mobile Dossier (`RemediationEngine` & `AdminGovernanceModal`)**: Solves the out-of-office Principal SRE approval bottleneck using HMAC-SHA256 signed Magic-Link Dossiers, scannable **QR codes** (`?mode=mobile-admin`), instant Discord/Slack/SMTP phone push, an **Investigation Hold Timer** (`👀 Acknowledge & Pause Timer`), **1% Shadow Dry-Run Sandbox**, and an automatic **Unreachable-Admin 5% Canary Break-Glass** fallback.
10. **Zero-Instrumentation Linux eBPF CO-RE Kernel Probes & Standard OTLP `/v1/traces` Receiver (`EbpfKernelProbeEngine` & `OtlpTraceReceiver`)**: Ingests standard OpenTelemetry `resourceSpans` payloads over `/api/v1/diagnostics/otlp/v1/traces` and correlates them with Linux eBPF kernel tracepoints (`syscalls:sys_enter_futex`, `tcp:tcp_retransmit_skb`, `sched:sched_switch`) to distinguish DB socket lock waits from CFS CPU cgroup throttling.

## 💻 Local Quickstart

### Prerequisites
- Python 3.12+
- Node.js 18+ & npm
- Docker & Docker Compose (optional for full containerized stack)

### 1. Clone Repository
```bash
git clone https://github.com/kartik-012/AIOps---Root-Cause-Correlator.git
cd AIOps---Root-Cause-Correlator
```

### 2. Backend Setup
```bash
cd backend
python -m venv venv
# Windows:
.\venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8001 --reload
```

Backend will be live at `http://localhost:8001` with Swagger docs at `http://localhost:8001/docs`.

### 3. Frontend Setup
```bash
cd ../aiops-frontend
npm install
npm run dev
```

Frontend will open at `http://localhost:5173`.

### 4. Running Verification Test Suite
```bash
cd ../backend
python -m pytest tests/ -v
```
